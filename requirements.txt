# Capped deliberately, not just "whatever is newest".
#   - 0.15 exposes NVFP4InferenceConfig and lets `use_dynamic_per_tensor_scale=False` run on the
#     Triton kernel. That is the only NVFP4 configuration measured faster than BF16 on this stack
#     (2.0-2.7x from M=2560 up); see docs/memo/dinov3_nvfp4_speedup_gate.md.
#   - 0.16 also works: the class is renamed but convert_fp32_to_fp4_packed is still there, which is
#     what the fast quantizer needs. Verified against the byte-equality gate.
#   - 0.17 drops convert_fp32_to_fp4_packed entirely, so the FP4 path falls back to
#     NVFP4Tensor.to_nvfp4 -- ~2x slower on quantization. It warns once at startup rather than
#     failing, so an upgrade silently costs the speedup.
# offload/server/model/dinov3_precision.py imports either class name, so it still runs on 0.17 --
# just slower. Re-measure before lifting this cap.
